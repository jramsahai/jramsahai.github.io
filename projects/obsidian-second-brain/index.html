Obsidian Second Brain

An AI agent that captures, files, links, and reviews notes in an Obsidian vault instead of manual filing

The problem

A note-taking vault only stays useful if someone keeps filing things correctly: routing a stray thought to the right project, linking a new note to the people and topics it touches, and periodically tidying up before it turns into a pile of orphaned pages. That upkeep is tedious enough that most people either drop it or let their notes system slowly rot.

The solution

This is a set of agent skills that let an AI agent run that upkeep inside an Obsidian vault: capturing new notes, routing them to the right project, person, or goal, linking related entries, and running a nightly consolidation pass that connects and organizes without inventing content. Separate skills cover project tracking, meeting notes, tasks, people notes, a daily journal, a knowledge base, and a monthly self-improvement pass, all coordinated through one shared set of vault conventions.

The skills never touch the vault's files directly. A Model Context Protocol (MCP) server sits between the agent and the vault, exposing a small set of intent-shaped tools instead of raw file access. The split is deliberate: the server owns the shape of every write — where a note goes, what its frontmatter looks like, that a repeat call changes nothing, that nothing is deleted — while the model owns the judgment, like which notes are worth connecting or what a summary should lead with. Machine edits are append-only, and every automated pass is wrapped in a git snapshot, so a night of agent activity is one reviewable, revertible commit rather than a diff you have to reconstruct by hand.

That same discipline extends to changing the skills themselves. A drift lint checks every skill's instructions against the server's actual tools so the prose can't silently fall out of sync, and a set of behavioral evals checks that a model reading a skill actually picks the right tool for a given capture. Once a month, a read-only skill looks at correction logs and eval results and proposes up to three specific wording changes with evidence attached — but it never edits its own instructions. A person reviews and merges each proposal by hand, and it only ships once the lint and evals stay green.

Tech stack

A TypeScript MCP server backs a set of markdown-based agent skills, with an evals harness and git-backed snapshots keeping automated changes honest.
