Agent Voice Bridge

Talk to a local AI agent CLI by voice from any device on your network, with speech kept entirely local

The problem

AI agent CLIs are powerful but keyboard-bound: you have to be sitting at the machine that runs them to use them. There was no way to just speak to one from a phone or another device, and pointing a microphone at a cloud speech service to get there would mean sending everything you say to a third party. I wanted a voice interface that worked from anywhere on my own network without any of that trade-off.

The solution

Agent Voice Bridge is a push-to-talk voice client paired with a local bridge service that runs on the same machine as the agent. You speak into a browser (or a bare command-line client), the bridge transcribes the audio locally, hands the text to the agent CLI, and speaks the reply back. The whole thing runs on your own hardware and is reachable only over Tailscale, so nothing leaves your network and nothing needs to be exposed publicly to use it from a phone or laptop elsewhere.

Each agent CLI is supported through a single small adapter, so no agent-specific logic leaks into the rest of the bridge; adding a new agent means writing one adapter file, not touching the core service. One choice that made spoken replies noticeably better: instead of injecting a fake system prompt into every turn, the bridge primes the voice session once with instructions to keep replies brief and speech-friendly, then sends plain transcript text on every turn after that. Replies are also run through a cleanup pass that strips markdown and other formatting before they reach the text-to-speech engine, while the client still gets the raw text for display.

Before any dedicated hardware existed, I defined a versioned HTTP API and wrote a bare reference CLI client against it with no browser, no JavaScript, and no audio codecs, just raw HTTP and PCM buffers. Getting that client to complete a full voice turn proved the API contract on its own, ahead of building anything a person would actually hold.

Tech stack

A Node.js bridge service coordinates local speech-to-text, agent adapters, and swappable text-to-speech backends, fronted by a browser client and reachable only over a private tailnet. It is macOS only for now, since it shells out to macOS-specific audio and speech tools.
